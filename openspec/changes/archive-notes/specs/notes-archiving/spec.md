## Purpose

Надає користувачам можливість детерміновано архівувати та відновлювати власні нотатки, переглядати розділені списки активних і архівованих записів, а також надійно ізолює приватні дані між різними користувачами.

## ADDED Requirements

### Requirement: Перемикання стану архіву нотатки
Система MUST дозволяти власнику нотатки перемикати стан архіву через ендпоінт `PATCH /api/notes/:id/archive` із суворою перевіркою булевого прапорця.

#### Scenario: Успішна архівація нотатки
- **WHEN** автентифікований користувач надсилає `PATCH /api/notes/:id/archive` із тілом `{"archived": true}` для власної активної нотатки
- **THEN** система встановлює `is_archived = 1`, повертає статус `200 OK` та оновлений об'єкт нотатки

#### Scenario: Успішне відновлення нотатки з архіву
- **WHEN** автентифікований користувач надсилає `PATCH /api/notes/:id/archive` із тілом `{"archived": false}` для власної архівованої нотатки
- **THEN** система встановлює `is_archived = 0`, повертає статус `200 OK` та оновлений об'єкт нотатки

#### Scenario: Відхилення некоректного типу даних
- **WHEN** користувач надсилає небулеве значення або порожній об'єкт у поле `archived`
- **THEN** система повертає статус `400 Bad Request`

### Requirement: Розділення активних та архівованих нотаток
Система MUST повертати активні нотатки за замовчуванням і архівовані лише за явним запитом клієнта.

#### Scenario: Отримання списку активних нотаток за замовчуванням
- **WHEN** користувач виконує `GET /api/notes` без параметрів
- **THEN** система повертає виключно нотатки поточного користувача зі станом `is_archived = 0`

#### Scenario: Отримання списку архівованих нотаток
- **WHEN** користувач виконує `GET /api/notes?archived=true`
- **THEN** система повертає виключно нотатки поточного користувача зі станом `is_archived = 1`

### Requirement: Ізоляція та авторизація доступу
Система MUST перевіряти права власності на нотатку безпосередньо у запитах до бази даних для операцій читання, архівації та видалення.

#### Scenario: Спроба читання чужої нотатки
- **WHEN** автентифікований користувач виконує `GET /api/notes/:id` для нотатки, створеної іншим користувачем
- **THEN** система повертає `404 Not Found`, не розкриваючи змісту та існування чужого запису

#### Scenario: Спроба архівації чужої нотатки
- **WHEN** автентифікований користувач виконує `PATCH /api/notes/:id/archive` для нотатки іншого користувача
- **THEN** система повертає `404 Not Found`, а статус нотатки в базі не змінюється

### Requirement: Гігієна відповідей сервера
Система MUST повертати лише публічні поля нотатки та ніколи не розкривати внутрішній ідентифікатор `user_id`.

#### Scenario: Перевірка полів у відповіді API
- **WHEN** користувач отримує нотатку через список або окремий запит
- **THEN** об'єкт містить `id`, `title`, `body`, `is_archived`, `created_at` і не містить `user_id`

### Requirement: Доступність та інтерфейс користувача
Інтерфейс користувача MUST надавати доступні вкладки фільтрації, семантичні кнопки дій та окремі стани для порожнього списку.

#### Scenario: Перемикання вкладок у браузері
- **WHEN** користувач перемикається між вкладками «Активні» та «Архів»
- **THEN** інтерфейс оновлює атрибут `aria-current="page"` на активній кнопці та показує відповідний список нотаток або відповідний текст порожнього стану
