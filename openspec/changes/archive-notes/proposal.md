# Proposal: Note Archiving & Secure Access

## Why

Користувачі застосунку нотаток накопичують застарілі записи, які захаращують основний робочий простір, але не повинні видалятися назавжди. Потрібна наскрізна можливість архівувати нотатки та відновлювати їх за потреби, із суворим дотриманням безпеки та ізоляції між користувачами.

## What Changes

- Додавання стану архівування (`is_archived`) для кожної нотатки у базі даних SQLite.
- Додавання серверного ендпоінта `PATCH /api/notes/:id/archive` для безпечного перемикання стану `is_archived` виключно власником нотатки.
- Оновлення спискового ендпоінта `GET /api/notes`: за замовчуванням повертаються лише активні нотатки, а за параметром `?archived=true` — архівні.
- Усунення засіяної вразливості витоку даних у `GET /api/notes/:id` (забезпечення перевірки `WHERE id = ? AND user_id = ?` та приховування внутрішнього `user_id`).
- Оновлення інтерфейсу користувача: додавання доступних вкладок навігації «Активні» / «Архів», кнопок «Архівувати» та «Відновити», індивідуальних порожніх станів та a11y атрибутів.

## Capabilities

### New Capabilities
- `notes-archiving`: Можливість архівувати та розархівовувати власні нотатки, переглядати розділені списки активних і архівних записів та захист від несанкціонованого доступу.
