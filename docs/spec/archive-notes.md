# Специфікація: Архівування нотаток (Note Archiving)

**Джерело:** OpenSpec change `archive-notes` (`openspec/changes/archive-notes/`)  
**Статус:** Agreed  
**Автор:** Pavlo Yeremenko  

---

## 1. Мета

Створити наскрізний механізм архівації та відновлення нотаток на всіх чотирьох рівнях застосунку (UI → API → база даних → авторизація), усунути засіяну вразливість витоку даних у `GET /api/notes/:id`, забезпечити безпеку та доступність інтерфейсу.

---

## 2. Таблиця рішень щодо неоднозначностей

| # | Питання | Рішення | Чому саме так |
|---|---|---|---|
| **D-1** | Як зберігати стан архіву в SQLite? | Колонка `is_archived INTEGER NOT NULL DEFAULT 0`. | Мінімалістично, детерміновано, швидко для індексації та фільтрації, уникає проблем із часовими поясами. |
| **D-2** | Який REST-контракт для архівації? | `PATCH /api/notes/:id/archive` із тілом `{"archived": boolean}`. | Ідемпотентний REST-метод із чіткою серверною валідацією типу. Повертає оновлену нотатку `200 OK`. |
| **D-3** | Як розділити активні та архівні нотатки в `GET /api/notes`? | За замовчуванням повертати лише активні (`is_archived = 0`), а за `?archived=true` — архівні. | Зберігає сумісність: усі 9 початкових тестів залишаються зеленими без змін. |
| **D-4** | Що повертати при спробі доступу до чужої нотатки? | `404 Not Found`. | Практика безпеки: не розкриває факт існування чужого ресурсу зловмиснику. Узгоджено з `DELETE /api/notes/:id`. |
| **D-5** | Де перевіряти права доступу на читання/зміну? | Безпосередньо в SQL-запиті: `WHERE id = ? AND user_id = ?`. | Запобігає витоку конфіденційних даних у пам'ять Node.js та виключає стан перегонів (TOCTOU). |
| **D-6** | Які поля повертати у відповіді? | Лише публічні поля: `id, title, body, is_archived, created_at`. | Сувора гігієна відповідей: поле `user_id` ніколи не віддається клієнту. |
| **D-7** | Як організувати UI для перегляду архіву? | Вкладки «Активні» / «Архів» над списком із семантичним `aria-current="page"`. | Найзручніший для сприйняття UX із чітким розділенням контексту та окремими порожніми станами. |

## 3. Критерії приймання (Acceptance Criteria)

- **AC-1:** КОЛИ автентифікований користувач надсилає `PATCH /api/notes/:id/archive` із `{"archived": true}` для своєї нотатки, ТОДІ нотатка отримує `is_archived = 1`, сервер повертає `200 OK` з оновленою нотаткою, і вона зникає з виклику `GET /api/notes`.
- **AC-2:** КОЛИ користувач робить `GET /api/notes?archived=true`, ТОДІ повертаються лише нотатки поточного користувача зі станом `is_archived = 1`.
- **AC-3:** КОЛИ користувач надсилає `PATCH /api/notes/:id/archive` із `{"archived": false}` для своєї архівованої нотатки, ТОДІ `is_archived` стає `0`, і вона повертається до активного списку `GET /api/notes`.
- **AC-4:** КОЛИ клієнт надсилає `PATCH /api/notes/:id/archive` із небулевим полем `archived` (наприклад, рядок `"true"` або відсутнє поле), ТОДІ сервер повертає `400 Bad Request`.
- **AC-5:** КОЛИ клієнт передає невалідний ID нотатки (наприклад, рядок `/api/notes/abc/archive` або не додатне число), ТОДІ сервер повертає `400 Bad Request`.
- **AC-6:** КОЛИ користувач намагається прочитати (`GET /api/notes/:id`) або заархівувати (`PATCH /api/notes/:id/archive`) нотатку, яка належить іншому користувачу, ТОДІ сервер повертає `404 Not Found`, не змінюючи даних у базі.
- **AC-7:** КОЛИ повертається відповідь для `GET /api/notes`, `GET /api/notes/:id` або `PATCH /api/notes/:id/archive`, ТОДІ в об'єкті нотатки відсутнє внутрішнє поле `user_id`.
- **AC-8:** КОЛИ користувач у браузері перемикає вкладки «Активні» та «Архів», ТОДІ інтерфейс оновлює `aria-current="page"`, показує відповідні кнопки («Архівувати» чи «Відновити») та правильний текст, якщо нотаток немає («Нотаток поки немає» або «Архівованих нотаток немає»).

## 4. Контракт API

```ts
// GET /api/notes?archived=true|false
// Header: x-user-id: <number>
// Response 200:
interface NoteResponse {
  id: number;
  title: string;
  body: string;
  is_archived: number; // 0 or 1
  created_at: string;
}

// PATCH /api/notes/:id/archive
// Header: x-user-id: <number>
// Body:
interface ArchiveRequestBody {
  archived: boolean;
}
// Response 200: NoteResponse
// Response 400: { error: string }
// Response 404: { error: "not found" }
```
